## Bug majeur trouvé en fin de refonte : Fraunces et Manrope n'étaient jamais appliqués

Symptôme : les titres paraissaient « plats ». Vérification en navigateur :

```
getComputedStyle(h2).fontFamily  → ui-sans-serif, system-ui, sans-serif, …
--font-serif (sur :root)         → ""   ← vide
--font-fraunces (sur :root)      → ""   ← vide
document.fonts.check('600 40px Fraunces') → false
```

Cause : `app/layout.tsx` posait les classes de variables next/font sur `<body>` :

```tsx
<body className={`${fraunces.variable} ${manrope.variable} font-sans`}>
```

alors que `app/globals.css` déclare dans `@theme` :

```css
--font-serif: var(--font-fraunces), Georgia, Cambria, serif;
```

Tailwind émet `@theme` dans `:root` (= `<html>`). Sur `<html>`, `--font-fraunces` n'existe pas,
donc `var(--font-fraunces)` est **non résolvable** → la propriété `--font-serif` devient invalide
et se propage vide à tout l'arbre. `font-family: var(--font-serif)` est alors une déclaration
invalide, abandonnée, et le navigateur retombe sur le sans-serif par défaut de Preflight.
Résultat : **aucun texte de l'app n'utilisait les polices prévues**, ni les titres ni le corps.

Correctif (pattern canonique Next + Tailwind 4) — variables sur `<html>` :

```tsx
<html lang="fr" className={`${fraunces.variable} ${manrope.variable}`}>
  <body className="font-sans antialiased">
```

Après correctif : `--font-serif` = `"Fraunces","Fraunces Fallback",Georgia,…`,
`h1` = Fraunces, `body` = Manrope, 2 fichiers woff2 chargés, `document.fonts.check` → true.

**Leçon générale** : dans Tailwind 4, tout `@theme` qui référence une variable définie par
next/font doit avoir cette variable sur `<html>`, pas sur `<body>`. Le symptôme est silencieux
(le build passe, aucune erreur console) — seul `getComputedStyle` le révèle.

Effet de bord : avec les vraies métriques serif, le hero reste sur 2 lignes à 390 px (39 px) et
1440 px (105,84 px) sans débordement, mais le paragraphe du hero passait sur des zones claires de
la photo sous `lg` (le dégradé horizontal ne protège plus la fin des lignes longues quand le texte
occupe toute la largeur) → ajout d'un voile uniforme `rgba(4,22,17,.42)` en `lg:hidden`.

## Piège d'environnement majeur : NODE_OPTIONS

`npm run build` échouait en boucle sur :

```
uncaughtException [Error: EPERM: operation not permitted, open '...\.next\trace']
```

Ce n'était ni un verrou de processus, ni le sandbox, ni le disque. La cause :

```
NODE_OPTIONS=--require=".../cli/vendor/shim/node-language-shim.cjs"
```

Le harnais précharge un shim Node dans **tous** les processus node, y compris le build Next,
et ce shim intercepte les appels fs → EPERM. Un `node -e "fs.openSync('.next/trace','a')"`
manuel fonctionnait, ce qui masquait la cause.

**Contournement : `NODE_OPTIONS="" npm run build`** (idem pour `next start`). Build en 1 min
au lieu d'échouer.

Autres pièges confirmés le même jour :
- `rm -rf .next` déclenche `SAFE_DELETE_BULK_CONFIRM_REQUIRED` dès ~235 fichiers. Utiliser
  `mv .next .next.old` (renommage, instantané) plutôt qu'une suppression.
- Le disque D: est passé à 0 octet libre à cause des copies de `.next` accumulées ; `ENOSPC`
  se manifestait par des erreurs de police au build (`Failed to fetch font`), pas par un message
  de disque plein. Toujours vérifier `df` avant d'accuser le code.

## Bug majeur trouvé au passage : les titres masqués se rognaient

Le hero révèle chaque ligne de titre via `<span class="overflow-hidden">` +
`translateY(110% → 0)`. Ce motif exige **une seule ligne visuelle par masque**.
Dès qu'une ligne passait à la ligne, la deuxième était rognée par `overflow:hidden`.

Le bug existait avant l'illustration, mais la colonne rétrécie l'a rendu systématique :
à 1280 et 1440, les scènes 2 (« Le guichet retrouve ») et 3 (« quand vient son tour »)
étaient coupées. Invisible sur la scène 1 seule.

Détection : `Range.getClientRects().length > 1` sur le span interne. Ne pas mesurer
`scrollHeight - clientHeight` — le `pb-[0.08em]` du motif fausse la mesure de 2 à 5 px
partout, y compris quand tout va bien.

Correctif : `.hero-title` passe de `clamp(3.15rem, 7.35vw, 7.25rem)` à
`clamp(2.5rem, 6vw, 6.6rem)` (et `5.6vw` entre 1024 et 1279 px). Validé sur
4 largeurs × 3 scènes = 12 combinaisons, zéro retour à la ligne.

**Règle à retenir** : toute modification du contenu des titres du hero, ou de la
largeur de leur colonne, doit être revalidée avec `title-clip.mjs`.

## Scène isométrique du hero (remplace l'illustration plate)

Direction retenue : « L'attente change de dimension », boucle de 10 s en 4 temps.
Décision technique : **2.5D isométrique en SVG, pas de WebGL**. L'isométrie est une
projection orthographique — pas de caméra, pas de lumière calculée — donc un rendu
identique à ~15 Ko de SVG au lieu de ~600 Ko de three.js. Une vraie scène 3D aurait
exigé des personnages modélisés et riggés dans Blender, hors périmètre.

`lib/iso.ts` : `iso(x,y,z) → ((x−y)·cos30, (x+y)·sin30 − z)` et `faces()` qui renvoie
les trois faces visibles d'un pavé (haut, y max, x max). La scène se décrit donc en
coordonnées 3D réelles ; les placements se recalculent, ils ne se dessinent pas à la main.

**Pièges rencontrés**
- L'écran mural doit rester droit : `matrix(0.866 0.5 0 1 e f)` avec v = −z. Avec
  `d = −1` le texte sort à l'envers. La variante `0 1` + y négatif donne un texte
  droit plaqué sur le plan du mur.
- Ordre de peinture : l'agent du guichet doit être peint **avant** le comptoir,
  sinon il apparaît debout sur le plateau.
- Un personnage assis : hanche à la hauteur du banc (11), cuisse vers +x, tibia qui
  redescend au sol. La première version faisait remonter le tibia.
- La carte ne fait que ~420 px : seuls deux nombres sont lisibles (ticket, compteur).
  Tout le reste est du texte de texture à 4–6 px, assumé.
- Le téléphone est en bas à gauche, jamais au centre : au centre il masquait la
  trajectoire du client vers le guichet.

**Vérification** : 16 animations en cours dans la figure (10 s / 2,4 s / 1,6 s),
47 Ko de pixels changent entre deux images à 1,6 s d'intervalle, 6 largeurs sans
débordement ni rognage. `prefers-reduced-motion` fige l'état résolu (ticket pris,
guichet éclairé) et masque le carton final.

Commit `a1218f2`.
