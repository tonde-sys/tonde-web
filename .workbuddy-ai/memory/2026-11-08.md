## Analyse complète du projet tonde-web

Contexte : TONDE = SaaS de gestion de files d'attente pour institutions d'Afrique de l'Est
(Burundi, RDC, Rwanda). 4 couches : backend FastAPI, mobile Flutter, web admin Next.js
(ce repo), desktop Tauri. Specs dans `.agents/skills/tonde_ecosystem` et `.agents/skills/tonde_web_admin`.

État constaté :
- Stack : Next 16.0.10, React 19.2, TS strict, Tailwind 4, shadcn/ui (68 composants), recharts, leaflet.
- Routes : `/` (landing 10 sections), `/login` (4 langues), `(dashboard)` : dashboard, queue, agents, locations, analytics, settings.
- Avancé : `agents/page.tsx` (1376 l.), `queue/page.tsx` (482 l.), `dashboard/page.tsx` (384 l.).
- Placeholders « Page en construction » : locations, analytics, settings (11 l. chacune).
- 100 % mock : aucun `fetch`/axios, aucune variable d'env, pas de `middleware.ts`, login = `setTimeout(1500)` puis `router.push('/dashboard')`.

Problèmes techniques relevés :
1. `leaflet`, `react-leaflet`, `@types/leaflet` présents dans package.json + lock mais ABSENTS de
   node_modules → `npx tsc --noEmit` échoue (TS2307 sur `AgencyMapClient.tsx`). Fix : `npm install`.
2. `npm run lint` inopérant : script eslint mais eslint absent des devDeps et aucune config.
3. `styles/globals.css` (125 l., thème clair oklch) orphelin, jamais importé → doublon de `app/globals.css`.
4. `components/theme-provider.tsx` jamais monté.
5. ~60 composants `components/ui/*` jamais utilisés (seule la landing en importe ~8).
6. Dashboard écrit en styles inline partout, alors que la spec interdit explicitement les styles
   inline et que les tokens shadcn existent dans `app/globals.css`. Double source de vérité design.
7. i18n non centralisé : 4 dictionnaires dupliqués (layout + login), textes FR en dur dans
   dashboard/queue/agents → viole la règle « aucun texte en dur ».
8. Mocks dupliqués entre layout/dashboard/queue/agents, aucune couche `lib/api`, `store`, `types`.
9. README obsolète (« landing page only ») alors que le dashboard existe depuis la PR #1.

Recommandation clé : trancher entre « dashboard maquette » et « dashboard produit ». Si produit,
la prochaine brique est la couche API (axios + TanStack Query + middleware auth), pas de nouvelles pages.
